# SongKit

Барабанная мастерская для iPhone и компьютера. Первый прототип: 4/4, 1–4 такта, бочка/малый/хэт, сетка до 1/32, тихие удары/акценты, undo/redo, воспроизведение с правками, локальный черновик, JSON и MIDI. Без аккаунтов и сервера данных.

## Запуск на Windows

Установите Node.js версии из `.node-version` (24.22.1), затем в PowerShell из папки проекта:

```powershell
npm ci
npm run dev
```

Откройте адрес из терминала. Для проверки production PWA и офлайна:

```powershell
$env:BASE_PATH = '/songkit/'
npm run build
npm run preview
```

Откройте `http://localhost:4173/songkit/`. Офлайн-режим работает в production на HTTPS или localhost. Обычный HTTP-адрес компьютера в локальной сети на iPhone не обеспечивает Service Worker. Для настоящей проверки iPhone используйте HTTPS-размещение.

## Управление

- Касание клетки ставит/убирает удар. Долгое нажатие или правая кнопка мыши открывает силу: тихий / обычный / акцент.
- Перенос: удержать существующий удар → «Перенести удар» → новое место на той же дорожке. На компьютере также работает перетаскивание мышью.
- Сетка меняет привязку, сохраняя все удары. Цифра внизу клетки обозначает удары между видимыми делениями. Выберите 1/32, чтобы увидеть их.
- Несколько тактов играют по кругу, выбранный такт редактируется независимо от звучащего.
- Черновик сохраняется локально, включая обновление страницы и закрытие. При возвращении звук запускается кнопкой. Экспорт проекта — отдельная резервная копия; очистка данных браузера удаляет черновик.
- «Новая партия» очищает рисунок с подтверждением. Undo возвращает ноты, пока сессия открыта. История undo не сохраняется между запусками.
- Тихие удары и акценты передаются в MIDI как velocity. Сейчас звуки синтезированные; акустический рок-банк предстоит выбрать с лицензией на распространение семплов.

## Проверки

```powershell
npm run check
npx playwright install chromium webkit
npm run test:e2e
```

Для E2E сначала соберите production с `BASE_PATH=/songkit/`, как выше. `check` выполняет форматирование, lint, типы, FSD/циклы, тесты с coverage, сборку и ограничения размера. Подробнее: `docs/TESTING.md`.

## GitHub и публикация

Репозиторий: https://github.com/SergeSokolan/songkit. Работа в ветке `feat/drum-editor-prototype`. Workflow `.github/workflows/ci.yml` проверяет PR и push в main/feat/**.

Публикация подготовлена, но выключена до проверки прототипа. Для включения после согласования: Settings → Pages → Source: GitHub Actions; Settings → Secrets and variables → Actions → Variables: `PAGES_ENABLED=true`. После успешных проверок push в main публикует тот же build-артефакт. Ожидаемый URL: https://sergesokolan.github.io/songkit/. Он не считается действующим до успешного deploy.

Настройте защиту main с обязательным job `verify`, PR и запретом force push. Публичное приложение не получает доступа к GitHub-учётным данным. Workflow не использует пользовательские токены.
