# Проверка публикации SongKit

Роль DevOps отвечает за проверку SHA и хода CI, публикацию проверенного `main` и дымовую проверку production. Временный стенд PR проверяет QA. Перед выпуском DevOps получает от QA ссылку на успешную автоматическую приёмку, номера задач и ожидаемую версию.

После слияния используй идентификатор запуска `Verify SongKit` для push в `main` и полный SHA коммита. Нужны авторизованный GitHub CLI, зависимости из `npm ci` и Chromium из `npx playwright install chromium`.

```powershell
pwsh -NoProfile -File scripts/verify-production.ps1 -RunId <id> -Sha <full-sha> -Version 0.5.0
```

Команда ждёт завершения указанного запуска, проверяет успешные `verify` и `deploy`, затем открывает production в чистом Chromium. Она проверяет номер версии, касание клетки и сохранение черновика после перезагрузки без сети. Для локального каталога браузеров перед запуском установи `PLAYWRIGHT_BROWSERS_PATH` в его абсолютный путь.

При ошибке зафиксируй SHA, ссылку на запуск и вывод команды. После исправления проверь следующий коммит и соответствующую ему публикацию. После успешной проверки следуй [процессу выпуска](RELEASING.md) для тега и GitHub Release.
