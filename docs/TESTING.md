# Проверка SongKit

Актуальна для 0.4.0-rc.1. Фактическая локальная база:182 unit/integration и 44 E2E Chromium/WebKit;5 тестов валидатора архитектуры отдельно. Результаты конкретного SHA на GitHub проверяются по CI, а не выводятся из локального прогона.

## Автоматические проверки

`npm run check`: форматирование, `version:check`, ESLint, TypeScript strict, FSD/cycles, Vitest с coverage моделей>=90%, production build и бюджеты. Новые модели каталогов входят в coverage. Пороги нельзя снижать ради зелёного CI.

Unit/property/integration: прямые и триольные ticks, границы, перенос, velocity, undo/redo, безопасный импорт/миграция, хранилище/ошибки/повреждение, точные scheduler timestamps, один старт/цикл, tempo, pause/resume, фон и аудиогонки. MIDI разбирается независимой midi-file; каждый брейк проверяется по ticks/velocity и сохранности внешних нот.

E2E после production `BASE_PATH=/songkit/`: `npm run test:e2e`. Playwright запускает preview сам, обычно порт 4173; SONGKIT_TEST_PORT позволяет выбрать другой. Chromium и WebKit mobile:редактирование, цикл обычный/тихий/удалить, явный перенос, смешанные сетки, точный IndexedDB до reload, экспорт, офлайн, каталоги, девять дорожек, закреплённый транспорт. На кнопках нет видимого текста и «В начало». Названия над рядами до 760px, слева на desktop, не уезжают при горизонтальной прокрутке. Проверены 360/390/430, альбом 844×390, desktop1280.

Браузеры установить: `npx playwright install chromium webkit`;Linux CI использует `--with-deps`. PLAYWRIGHT_BROWSERS_PATH задаёт отдельный кеш.

## Документация и снимки

После изменения UI или версии пересобрать `/songkit/`, выполнить `npm run docs:screenshots`, просмотреть PNG, затем `npm run format:check`. Снимки и manifest должны иметь версию пакета;version:check сравнивает package/lockfile/changelog/manifest и наличие файлов. Он не заменяет визуальную оценку.

[Текущие снимки и способ генерации](screenshots/README.md). Исторические before-* показывают 0.3.0 и не обновляются как текущее состояние. Остальные скриншоты, трейсы и coverage сохраняются CI как artifacts.

## Ручная приёмка iPhone13

Записать iOS, Safari, версию приложения, SHA и способ запуска. Открыть HTTPS, дождаться «Доступно офлайн», проверить и Safari, и PWA Home Screen.

1. Играть и редактировать 10 минут:нет слышимых пропусков/двойных ударов/зависаний.
2. Цикл касаний, двойные быстрые касания, удержание 1–2 секунды, scroll/pointercancel:нет случайной правки/выделения/меню. Проверить явную динамику и перенос.
3. Прямые/триольные сетки, несколько тактов, смешанные ноты, Undo/Redo;переключение не меняет рисунок. Пауза сохраняет позицию, Play продолжает.
4. Девять дорожек, томы 1/2/3, названия над рядами, вертикальная/горизонтальная прокрутка, портрет/альбом, крупный текст. Цели>=44px.
5. Сокращение фразы с предупреждением/отменой, импорт ошибочного/старого JSON, темп на ходу.
6. Сворачивание/блокировка/закрытие/reload:подтверждённый черновик сохранён, запуск только по кнопке.
7. Авиарежим после прогрева:reload, play, редактирование, JSON/MIDI в Files, обратный импорт. Bluetooth отдельно от встроенного динамика.
8. Беззвучный режим и громкость медиа, «Восстановить звук», слышимость теста. Успешный Audio Session API не доказывает наличие слышимого звука.
9. Все жанры/длины брейков и 15 грувов:зацикливание, groove→fill→groove, медленный 60 и рабочий 100BPM, металл дополнительно 140. Сравнить обычный long/short и обратный short/long swing;записать замечания по каждой карточке.
10. Инструментально измерить p95 визуального отклика<100ms;не объявлять успех по ощущениям или desktop WebKit.

Эти ручные проверки пока не выполнялись. Нет обещания абсолютного сохранения последних миллисекунд при аварии/очистке браузера. Откат на 0.3 не понимает триоли:до отката сохранить JSON и исходные данные.

Бюджеты: startup JS gzip<=300KiB, полный офлайн-пакет<=8MiB. Значения измеряются build/budget;реальные аудиотайминги и производительность iPhone — отдельно.
