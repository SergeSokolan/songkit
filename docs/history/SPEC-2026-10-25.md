# SongKit — спецификация для SOL, v0.1

Дата: 2026-10-25. Статус: спецификация, реализация не начата. SongKit — рабочее название; уникальность бренда не проверена.
Локальный проект: C:\Users\sokol\Documents\wibecoding\songkit. Git remote: https://github.com/SergeSokolan/songkit.git (public), локальное клонирование подтверждено. Не создавать новый remote и не перезаписывать существующие файлы.

## Продукт

Бесплатный барабанный редактор PWA, русский интерфейс, разработка на Windows. Основное устройство проверки iPhone 13; точную версию iOS записывать в отчёте. Без аккаунтов, backend, аналитики и передачи партий. После первой полной загрузки работает офлайн. В будущем возможен подбор аккордов, но сейчас никаких его функций, заглушек и моделей не создавать.

## Стек

TypeScript strict, React, Vite, нативный Web Audio, VexFlow, IndexedDB для черновика, Service Worker/Cache Storage для ресурсов. MP3 кодировать локально в Worker; библиотеку выбрать после проверки лицензии, Safari и размера. npm с lockfile, npm ci, закреплённая поддерживаемая Node LTS. Проверять реальные API и совместимость выбранных версий перед использованием.

## FSD

Зависимости только вниз по слоям, запрет прямых импортов соседних слайсов, deep imports и циклов. Публичные API через index.ts. Проверять ограничения автоматически в CI. Не создавать пустые слои.

- app: запуск, провайдеры, SW, композиция зависимостей.
- pages/drum-editor: композиция пользовательских сценариев.
- widgets: drum-grid, transport-panel, score-view, phrase-timeline.
- features: edit-pattern, playback, manage-fills, export-pattern, draft-recovery.
- entities/drum-pattern: единая модель партии, инструменты, чистые команды, валидация и история.
- shared: универсальные UI-примитивы, утилиты, инфраструктура без барабанной бизнес-логики.
  Features взаимодействуют через композицию на вышележащем слое. Домен не зависит от React, DOM, Tone.js, VexFlow или хранилища. Звук, нотация и экспорт читают одну модель, не ведут собственные расходящиеся версии партии.
  Документы: README.md, AGENTS.md, docs/SPEC.md, docs/ARCHITECTURE.md, docs/TESTING.md, docs/DECISIONS.md, лицензии ресурсов. AGENTS.md закрепляет FSD, команды проверок, запрет расширять scope, выдумывать API и отключать проверки ради зелёного CI.

## Музыкальные правила

PPQ=960 целых отсчётов на четверть. Длина такта = PPQ*4*numerator/denominator. Позиции внутри [0, длина фразы). Float-секунды не источник музыкальной истины.
Pattern: schemaVersion, tempo, timeSignature, barCount, events. Event: id, instrument/articulation, tick, velocity 1..127. Представление редактора хранится отдельно. Одинаковые instrument/articulation/tick не дублируются, одновременные разные инструменты допустимы.
Первая полная версия: 2/4, 3/4, 4/4, 6/8; 1–16 тактов; 40–240 BPM четвертями в минуту, единица темпа явно показана. Вертикальный прототип только 4/4 и 1–4 такта.
Сетки 1/4, 1/8, 1/16, 1/32. Смена сетки не меняет события. Дробление не удлиняет такт. Триоли, свинг и microtiming вне v1; PPQ допускает их позднее. Сокращение фразы или смена размера с потерей событий требуют предупреждения и отмены.
Ноты и паузы вычислять по событиям с правильной группировкой долей и голосами. Каждый голос точно заполняет такт. Длительность семпла независима от нотной длительности. VexFlow рисует ноты, но не заменяет алгоритм нотации. До реализации закрепить эталоны для синкоп, одновременных ударов, пауз, 32-х и 6/8.

## Редактор

Начально видны бочка, малый, хэт; другие дорожки раскрываются. Касание пустой клетки добавляет, занятой удаляет. Долгое нажатие показывает Тихий/Обычный/Акцент без удаления; провести пальцем к варианту и отпустить. Альтернатива — явные доступные кнопки. Drag с порогом движения переносит с привязкой. Undo/redo обязательны.
Velocity 35/80/115 — стартовые значения, настроить на банке. Разные размеры маркеров и подписи, не только цвет. Ghost на стане в скобках, акцент >. Rimshot отдельная артикуляция, не уровень силы.
Увеличение доли для 32-х, без 32 крошечных целей на телефоне. Целевой размер управления 44 CSS px, safe areas, портрет/альбом, прокрутка без случайной правки.

## Аудио

Старт после жеста пользователя и декодирования звуков. Scheduler по AudioContext clock с ограниченным lookahead, анимация отдельно. Правки влияют на ближайшие ещё не запланированные события. Окно планирования измерить и документировать; не обещать нулевую задержку.
Stop отменяет источники и будущие удары. Повторный Play не удваивает scheduler. Темп меняется на ближайшей доле, размер/длина цикла на границе такта. Закрытый хэт/педаль глушит открытый.
При suspend/background приостановить, сохранить позицию; не проигрывать накопленные удары при возврате. Возобновление кнопкой. Фоновое воспроизведение не обязательно.

## Банк

Сухая нейтральная рок-установка: бочка, малый обычный/rimshot, хэт закрытый/открытый/педаль, три тома, крэш, райд/колокол. Желательны velocity layers и 2–3 варианта основных ударов, прежде всего малого/хэта. Ghost — сила удара.
Банк пока не выбран. Обязательна лицензия на распространение самих семплов в приложении, например CC0; сохранить происхождение и текст лицензии. Нельзя брать звуки GarageBand или случайные интернет-файлы. Семплы полностью локальны до игры. Вариации детерминированы seed для тестов/экспорта.

## Брэйки

Фраза по умолчанию 4 такта, до 16. Выделение участка по сетке. Библиотека rock/pop/funk по плотности; конкретный каталог фиксировать перед этапом.
Локальный генератор правил без облачного AI учитывает метр, длину, плотность и акценты. Минимум 3 воспроизводимых варианта. Предпросмотр недеструктивный. Применение заменяет только выбранные дорожки внутри [start,end), сохраняет события снаружи, не меняет длину фразы и отменяется одной командой. Брэйк хранится обычными событиями. После участка продолжается основной рисунок.

## Черновик и офлайн

Черновик локально в IndexedDB после команд, короткое объединение частых правок <=250 мс. visibilitychange/pagehide — дополнительная защита, не единственный способ записи. Не обещать сохранение незавершённой транзакции при аварийном завершении.
Восстанавливать ноты, параметры, выделение, масштаб/прокрутку и остановленную позицию. После сворачивания, блокировки, reload и закрытия. Сохранение после reload/закрытия — рекомендованное уточнение исходного требования, явно довести пользователю. Автозапуск звука запрещён.
Версионирование схемы, атомарность, безопасные миграции. Повреждение и отказ/квота хранилища не должны молча уничтожать данные: уведомить, предложить экспорт. Очистка через явную команду с подтверждением. Браузер может очистить свои данные, экспорт проекта доступен всегда.
SW кеширует UI, шрифты, звуки, нотацию и экспорт. Индикатор готовности офлайн только после проверки полного набора. Обновление не перезагружает активную сессию; применять после сохранения и действия пользователя. Проверить scope и пути при размещении под repository subpath. Никаких runtime-CDN, аналитики, внешних шрифтов и передачи партий; хостинг получает обычные запросы ресурсов.

## Экспорт

JSON проекта с schemaVersion и строгой валидацией. Ошибочный импорт не меняет текущую партию; лимиты размера/событий.
MIDI: GM percussion channel 10 (индекс 9), карта ударных, tempo/time signature, velocity, длительность фразы. Проверять независимым парсером.
MusicXML: ударная нотация, голоса, паузы, размер, ghost/акценты. Проверка структуры и ручного импорта в Guitar Pro. Без установленной программы не заявлять успешную совместимость. MIDI не гарантирует идентичный нотный вид.
MP3: offline render, Worker encoder, прогресс, отмена, ограничение повторов, хвосты тарелок. Соответствие семплам/темпу/velocity редактора. WAV может быть дополнительным, но не заменяет MP3.

## Тестирование и критерии

Vitest, Testing Library, fast-check, Playwright Chromium+WebKit. WebKit-эмуляция не заменяет iPhone.
Unit/property: арифметика метра и 32-х, границы событий, неизменность при смене сетки, undo/redo, velocity, детерминизм брейков, сохранность событий вне брейка, заполнение такта каждым голосом.
Integration: модель→scheduler, единственный scheduler, stop/resume, изменения на границе цикла, tempo, сериализация/миграции/квота/повреждение; MIDI независимый разбор, MusicXML структура, audio export на синтетических импульсах с проверкой моментов ударов. Mock clocks не доказательство реального аудиотайминга.
E2E: создание, дробление, ghost/accent, перенос, undo, брейк, save/import, экспорт; reload восстанавливает черновик; после прогрева кеша авиарежим и reload, полный сценарий включая экспорт; обновление SW сохраняет черновик.
Ручная матрица iPhone 13: 10 минут игры с правками; блокировка, другое приложение, выгрузка вкладки, Home Screen, офлайн, сохранение Files, обе ориентации. Bluetooth проверять отдельно, его задержка не равна задержке scheduler.
Цели измерений: p95 визуального отклика <100 мс; без слышимых пропусков и двойных ударов за 10 минут; сжатый стартовый JS <=300 KiB без ленивых модулей; полный офлайн-пакет целевой <=8 MiB. Превышения документировать и обсуждать, не менять пороги молча. Прогресс первой загрузки на медленной сети.
Доменное ядро >=90% statements/branches. Покрытие не заменяет смысловые тесты. Каждый исправленный баг получает regression test. Не ограничиваться snapshots/наличием компонентов.

## CI/CD

PR: npm ci, lint, typecheck, FSD/cycle checks, unit/integration+coverage, production build, Playwright и budgets. Артефакты отчётов/traces при сбоях. Не отключать проверки и не менять ожидания ради зелёного CI.
Защитить main проверками и PR при доступности на тарифе. Небольшие тематические изменения. Не обещать, что тесты исключат все ошибки.
CD только main после проверок, публиковать тот же проверенный build. PR не деплоит production. Минимальные workflow permissions; не запускать непроверенный PR-код с секретами; Actions закрепить проверенными SHA.
Кандидат — GitHub Pages через Actions, доступность зависит от приватности/тарифа. Не открывать исходники ради Pages. Подготовить откат релиза и учесть совместимость черновиков.
