# Архитектура

FSD-слои: app → pages → widgets → features → entities → shared. Слайсы соседнего слоя не связаны. Общая композиция находится в pages/drum-editor. app запускает восстановление и PWA; не создаёт отдельную модель ритма.

entities/drum-pattern — чистые функции и типы Pattern/Event/Draft, PPQ, валидация, история. Не зависит от UI, аудио или браузерного хранилища. События привязаны к музыкальному времени, а не пикселям.

features/edit-pattern — React-обёртка истории. features/playback — тестируемый Scheduler с внедряемыми аудиочасами, DrumAudio-адаптер к Web Audio AudioContext и lifecycle-hook. Scheduler заполняет очередь на 75 мс вперёд, проверяется каждые 25 мс, стартовая задержка 25 мс. Максимальное ожидаемое окно принятия правки около 75 мс; реальные показатели iPhone ещё предстоит измерить. При просрочке очереди больше 150 мс останавливается вместо проигрывания накопленных ударов. Анимация не задаёт аудиотайминг.

features/draft-recovery — IndexedDB и последовательная очередь записей. Музыкальная команда вызывает сохранение через 150 мс тишины; уход в фон дополнительно запрашивает запись. Данные валидируются перед записью и восстановлением. Ошибка чтения блокирует перезапись до явной новой партии. Абсолютная сохранность последних миллисекунд при аварийном завершении не гарантируется.

features/export-pattern — независимый MIDI encoder и JSON. MIDI format 0, PPQ 960, percussion channel index 9, GM 36/38/42, note-off через 60 ticks. Длина трека равна фразе, включая паузы. Тесты декодируют файл отдельной библиотекой midi-file.

widgets/drum-grid и transport-panel — представление и обработка жестов через callbacks; не импортируют features. Экран связывает команды, аудио, историю, экспорт и черновик.

SW генерируется Workbox при production build. Прекеш содержит все локальные файлы приложения, включая звуки. Обновление не активируется принудительно. Черновик хранится отдельно от кеша ресурсов. Всё размещается относительно BASE_PATH, поэтому GitHub Pages subpath проверяется в E2E.

`scripts/check-architecture.mjs` использует TypeScript AST для проверки относительных импортов, публичных API и циклов. Не вводите aliases без расширения проверки архитектуры.

Набор инструментов входит в Pattern v2. Базовые kick/snare/hat обязательны; опциональные дорожки добавляются чистой командой addInstrument и отменяются общей историей. Порядок INSTRUMENTS задан снизу вверх; displayInstruments возвращает порядок DOM сверху вниз. Каталог содержит подписи, GM-ноты и семейства иконок. parsePattern мигрирует v1, сохраняя события; оболочка Draft остаётся v1, поскольку её поля не менялись. Все девять компактных WAV загружаются до Play, поэтому новую дорожку можно добавить без сетевого запроса во время игры.

features/manage-fills — генератор, оригинальная библиотека и чистое применение внутри полуинтервала. Страница компонует предпросмотр с единственным playback Scheduler через AuditionSelector. Подтверждённая Pattern остаётся источником сохранения и экспорта. История возвращает revision, чтобы никакой Undo не оживлял устаревший preview. Подробнее: FILLS.md. TempoControl внутри transport-panel получает диапазон из сущности и передаёт только подтверждённые команды через страницу; временное значение барабана локально виджету.
