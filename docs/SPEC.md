# Спецификация SongKit

Актуальна для **0.4.0**, 2026-10-28. Изменения PR #18 приняты пользователем и объединены в main. Исходное задание и последовательные уточнения сохранены в [истории](history/SPEC-2026-10-25.md); они не заменяют текущие правила ниже.

## Продукт и объём

Локальный барабанный редактор PWA с русским интерфейсом для телефона и компьютера. Без backend, регистрации, аналитики, runtime-CDN и передачи партий. Репозиторий: https://github.com/SergeSokolan/songkit. Рабочая папка — корень текущего checkout, без жёсткой привязки к старому пути.

Текущий объём:4/4,1–4 такта, девять инструментов, прямые и две триольные сетки, динамика, история, звук, брейки, грувы, мобильный темп, черновик, MIDI/JSON, офлайн. Другие размеры, нотный стан/VexFlow, акустический банк, MusicXML и MP3 — будущие задачи. Подбор аккордов вне объёма.

## Стек и архитектура

TypeScript strict, React, Vite, нативный Web Audio, IndexedDB, Service Worker/Cache Storage. Версии зависимостей точные, lockfile обязателен; Node из `.node-version`. FSD: app→pages→widgets→features→entities→shared, публичные API, без импортов между соседними слайсами, deep imports и циклов. Домен не зависит от React, DOM, аудио или хранилища. См. [архитектуру](ARCHITECTURE.md).

## Единая музыкальная модель

PPQ=960, все позиции — целые ticks. Такт 4/4=3840, события внутри `[0,3840*barCount)`. UI, аудио и экспорт читают одну Pattern. Tempo40–240 BPM четвертями. Pattern v2: instruments, tempo, timeSignature, barCount, events. Событие: id, instrument, tick, velocity1–127. Одинаковые instrument/tick не дублируются. Есть безопасная миграция Pattern v1; оболочка Draft остаётся v1.

Сетки 1/4,1/8,1/16,1/32 имеют шаг 960/480/240/120;1/8T и 1/16T — шаг 320/160 и 12/24 клетки на такт. Grid хранит числовые прямые значения и явные строки 8T/16T. Допустимые позиции — объединение кратных 120 и 160; это не произвольные tuplets. Максимум 48 позиций на инструмент/такт,1728 событий на 4 такта/9 инструментов. Смена сетки не квантует ноты; счётчик показывает удары между текущими делениями. Прямая и триольная сетки смешиваются. Глобальный swing не применяется.

## Инструменты и редактор

Базовые kick/snare/hat обязательны; остальные добавляются явно. Сверху вниз: крэш 2, крэш 1, райд, хэт, том 1, том 2, том 3, малый, бочка. Идентичности неизменны: tom1=HIGH TOM/GM50, tom2=MID TOM/GM47, tom3=FLOOR TOM/GM43. GM остальных: kick36, snare38, hat42, ride51, crash1=49, crash2=57.

Каждое завершённое касание: пусто→обычный 80→тихий 35→пусто, одна команда истории. Импортированный акцент первым касанием становится обычным. Акценты 115 и произвольные валидные velocity сохраняются в модели и экспорте. Удержание/contextmenu не открывает панель, не выделяет текст. Scroll/pointercancel не редактируют клетку.

«Изменить / перенести удар» открывает явный выбор клетки и панель динамики/переноса/удаления; мышью доступен drag. Undo/Redo едины для нот, инструментов и шаблонов. Сокращение фразы с потерей нот требует предупреждения и отменяется.

На ширине до 760 CSS px полное название инструмента находится над рядом и закреплено слева при горизонтальной прокрутке. Колонка имён сбоку отсутствует; на desktop подписи слева. Цели не меньше 44px, мелкая сетка прокручивается в собственном контейнере. На 390px сетка 1/8 показывает 7 полных клеток; область нот 380px. Заголовок добавляет 28px высоты на дорожку. Учесть safe-area, портрет/альбом и крупный текст.

## Транспорт и звук

Две кнопки воспроизведения — в панели темпа и непосредственно над сеткой. Только иконки: треугольник/два столбика; aria-label и aria-busy доступны скринридеру. Панель у сетки sticky и не создаёт отдельный транспорт. Кнопка «В начало» удалена, её prop/стили/неиспользуемая иконка удалены. Внутренний reset используется только при замене партии новой, импортом или примером.

Play после пользовательского жеста и декодирования локальных звуков. Пауза глушит источники и сохраняет позицию; продолжение явным Play. Подготовка блокирует повторный запуск. Один Scheduler с Web Audio clock: шаг 40ticks для общей базы прямых/триольных событий, lookahead75ms, poll25ms, start25ms. Темп меняется на ближайшей доле, длина — на границе такта. При просрочке более 150ms остановка вместо накопленной очереди. Это параметры алгоритма, не доказательство реального тайминга iPhone.

При background/suspend — пауза, без автозапуска при возврате. «Восстановить звук» пересоздаёт контекст и запускает тест бочки/малого/хэта. Resume ограничен 3 секундами, поздние результаты не заменяют новый запуск. Запрашивается доступный Audio Session playback; без API обычный Web Audio. Видимость физического переключателя и слышимость не определяются. Звуки — собственные синтезированные WAV, CC0; чужие семплы без лицензии запрещены.

## Брейки и базовые ритмы

Основной путь брейков: выбранный такт→пять жанров→¼/½/1 такт→именованная карточка→предпросмотр→применение. Последние 1/2/4 доли такта, размер и длина фразы неизменны.33 оригинальные учебные адаптации, точные ticks/velocity и источники семейств в [каталоге](FILL-CATALOG.md). RLKK — целые группы шестнадцатых, RLK — триоли, RLRLKK — секстоли. Никакой скрытой обрезки и события на исключённой правой границе.

Базовые ритмы отдельно:15 оригинальных адаптаций, по 3 на рок/металл/поп/фанк/джаз. Полный такт повторяется в выбранных тактах, темп пользователя сохраняется. Обычный swing согласован как long/short, обратный — short/long; последнее обозначено учебным вариантом, а не общепринятым стандартом. Инструменты имеют отдельные события. См. [каталог грувов](GROOVE-CATALOG.md).

Предпросмотр не сохраняется в проект, выбирается через тот же Scheduler. Применение заменяет перечисленные дорожки внутри полуинтервала, сохраняет всё остальное, отменяется одним Undo. Недостающие дорожки добавляются только после явного разрешения. Генератор и произвольный участок — дополнительный режим. Все данные локальны и доступны офлайн. Музыкальная оценка человеком ещё открыта.

## Черновик, экспорт и офлайн

IndexedDB: последовательные записи после 150ms тишины, pagehide/visibilitychange — дополнительная защита. Сохраняются подтверждённая партия, выбранный такт/сетка/scroll и остановленная позиция. Undo не сохраняется. Повреждение/ошибка чтения блокирует перезапись до явной новой партии, ошибка записи предлагает экспорт. Не обещать абсолютную сохранность при аварии или очистке браузером.

JSON — строгая валидация, ограничение файла 1MiB; ошибочный импорт не меняет текущую партию. MIDI format0, PPQ960, GM percussion channel10/index9, tempo, timeSignature, velocity, точная длина фразы. Независимая проверка midi-file. Нотация/MusicXML/MP3 пока не реализованы.

Workbox кеширует UI и все локальные звуки; индикатор готовности только после прогрева. Обновление не перезагружает активную сессию автоматически. Пути и scope учитывают `/songkit/`. Откат на 0.3 не поддерживает триольные ticks/grid: сначала экспортировать JSON и сохранять исходный черновик.

## Приёмка, версии и публикация

Перед сдачей: `npm run check`, production `BASE_PATH=/songkit/`, `npm run test:e2e`, после форматирования `npm run format:check`. Доменные пороги >=90%, без ослабления ради CI; исправления багов начинаются с regression test. Бюджет startup JS gzip<=300KiB, офлайн<=8MiB.

Реальный iPhone13/Safari/PWA,10 минут игры, Bluetooth, крупный системный текст и слуховая оценка не заменяются Chromium/WebKit. Фактические результаты и ограничения в [отчёте](BACKLOG-2026-10-27.md) и [плане тестов](TESTING.md).

Версии SemVer, CHANGELOG, аннотированные Git-теги и GitHub Releases — по [процессу релиза](RELEASING.md). Скриншоты обновляются под ту же версию. PR проверяет CI; main после зелёного verify может публиковать только проверенный артефакт, PAGES_ENABLED управляет CD. Пользователь явно принял изменения и разрешил применить их на main.
