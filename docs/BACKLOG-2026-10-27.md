## Геометрия до/после

Измерения Chromium, CSS px, сетка 1/8, одинаковый масштаб страницы. Внешние потери — вся ширина вне колонки имён и области нот (включая поля и рамку). Прежняя минимальная клетка фактически была 43.625px; новая — 45.625px, чтобы выдержать минимум44 с промежутками. Высота мобильной клетки54px сохранена. Контейнер сетки прокручивается, колонка имён остаётся на месте.

| Viewport | Внешние потери до→после | Имена до→после | Ноты до→после | Полные клетки до→после |
| -------- | ----------------------- | -------------- | ------------- | ---------------------- |
| 360      | 42→10                   | 78→56          | 240→294       | 5→5                    |
| 390      | 58→10                   | 78→56          | 254→324       | 5→6                    |
| 430      | 58→10                   | 78→56          | 294→364       | 6→7                    |

На390 получено +70px и +1 полная клетка. Цель +2 при текущей колонке имён недостижима без изменения масштаба: 7 целей по44px и 6 промежутков по5px требуют338px, доступно324px. Цели касания не уменьшались. Вся страница не прокручивается горизонтально. Альбом844×390 и desktop1280 проверены с девятью дорожками.

## Проверки

- `npm run check`: форматирование, ESLint, TypeScript, пять тестов архитектурного валидатора, FSD/cycles, 182 unit/integration, coverage, production build, budgets.
- Coverage (включая новые модели каталогов): statements99.02%, branches97.51%, functions100%, lines100%; пороги не снижены.
- Production build выполнен с `BASE_PATH=/songkit/`; стартовый JS gzip87.3KiB/300KiB, офлайн-пакет725.2KiB/8192KiB.
- `npm run test:e2e`: 44 сценария Chromium + WebKit. Проверяются цикл касаний, перенос, смешанные сетки, Undo/Redo, точное сохранение IndexedDB, JSON/MIDI, предпросмотр/применение каталогов, офлайн, девять дорожек и закреплённый транспорт на360/390/430/844/1280.
- Независимый MIDI-парсер сравнивает ticks/velocity каждого брейка; scheduler-test проверяет точное время смешанных прямых/триольных ударов.
- До исправлений воспроизведены красными regression-тестами порядок томов, цикл касаний, открытие при удержании/contextmenu и пропуск триольных нот scheduler.

Один из прогонов WebKit выявил неполное сохранение ожидаемого рисунка перед reload в E2E. Проверка усилена: подтверждает отображённый удар и точные события в IndexedDB до перезагрузки, а не только текст статуса сохранения. Это не считается доказательством абсолютной сохранности при аварийном завершении браузера.

Реальные Safari/iPhone, 10 минут игры, Bluetooth, системный крупный текст и слуховая музыкальная валидация не выполнялись. При откате на0.3 сначала экспортировать JSON: старый редактор не поддерживает новые триольные позиции и grid.

## Уточнение пользователя: названия над рядами на телефоне

По следующему запросу пользователя мобильная колонка имён слева заменена полными названиями над каждым рядом (ширина до760 CSS px). При горизонтальной прокрутке название остаётся у левого края видимой сетки. На desktop подписи остаются слева. Размеры целей не уменьшались; каждый ряд стал выше на28px за счёт заголовка.

| Viewport | Область нот со слева расположенными именами | С именами сверху | Полные клетки до→после |
| -------- | ------------------------------------------- | ---------------- | ---------------------- |
| 360      | 294                                         | 350              | 5→7                    |
| 390      | 324                                         | 380              | 6→7                    |
| 430      | 364                                         | 420              | 7→8                    |

Измерения Chromium, 1/8, одинаковый масштаб. На430px весь ряд из8 клеток помещается без горизонтальной прокрутки. Цель +2 клетки относительно исходной версии достигнута на390px: 5→7. Скриншоты выше фиксируют предыдущий вариант с боковыми подписями; актуальные превью остаются в локальных артефактах тестов.

Повторно прошли npm run check (182 unit/integration), production build с BASE_PATH=/songkit/, все44 E2E Chromium/WebKit и format:check. В E2E добавлены проверки положения заголовков над рядами, их закрепления при горизонтальной прокрутке, полной ширины клеток и сохранения desktop-раскладки. Реальный iPhone отдельно не проверялся.
