# Правила работы с SongKit

Прочитайте docs/SPEC.md, docs/ARCHITECTURE.md и docs/DECISIONS.md перед изменениями.

- Текущий этап A/B: прототип 4/4, 1–4 такта, три инструмента, динамика, воспроизведение, MIDI/JSON, черновик и офлайн. Не добавляйте следующий этап без задачи пользователя.
- FSD: импорты вниз по слоям, публичные API слайсов, без связей соседних слайсов, deep imports и циклов. Не прячьте бизнес-логику в shared.
- Доменные позиции — целые ticks, PPQ=960. Единственная модель для UI, звука и экспорта. Смена сетки не квантует существующие ноты.
- Проверяйте документацию и установленные типы библиотек. Не придумывайте API. Версии зависимостей точные, package-lock.json обязателен.
- Не передавайте партии в сеть, не добавляйте аналитику и runtime-CDN. Не включайте чужие семплы без лицензии на распространение.
- Не перезаписывайте чужие изменения, историю Git, повреждённый черновик или пользовательские файлы молча.
- Для исправления бага сначала создайте воспроизводящий regression test. Не отключайте проверки, не ослабляйте пороги и не меняйте ожидания ради зелёного CI.
- Перед сдачей: npm run check; production build с BASE_PATH=/songkit/; npm run test:e2e. После форматирования npm run format:check.
- Автоматический WebKit не заменяет настоящий Safari. Не заявляйте проверки устройства или CI, если их не выполняли. Пишите конкретные ограничения.
- Публикация production выключена переменной PAGES_ENABLED до согласования готового результата.
